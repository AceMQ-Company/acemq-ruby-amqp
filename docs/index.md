# AceMQ for Ruby

A Ruby client for AceMQ messaging over AMQP, speaking the same wire contract as
the [Java](https://acemq.org/), [Go](https://acemq.org/acemq-go-amqp/),
[.NET](https://acemq.org/acemq-dotnet-amqp/) and Python libraries: the same
reserved headers, the same defaults, the same retry arithmetic. A Ruby consumer
reads what a Java producer writes.

That claim is pinned rather than asserted. The fixtures under `spec/fixtures/`
were generated by the Java implementation and are shared with Go, .NET and
Python: `envelope-fixtures.json` pins the headers, and `contract-fixtures.json`
pins the retry schedule, the queue names and the topology. Specs read both and
hold this library to them. A port that hand-copies a contract out of
documentation acquires a difference nobody notices until two languages disagree
in production — see [how the five libraries are kept in
step](testing.md#the-cross-language-fixtures), including the places they do not
yet agree.

## A message, end to end

```ruby
require "acemq/amqp"

include AceMQ::AMQP

mq = Connection.open("amqp://guest:guest@localhost:5672",
                     origin: "checkout@pod-7",
                     retry_policy: RetryPolicy.exponential(5, 1, 60))

Topology.new
        .exchange("orders-events", :topic)
        .queue("orders.new", dead_letter: true)
        .binding("orders.new", "orders-events", "order.#")
        .apply(mq)

mq.publish({ "order_id" => "A-1" }, to: "order.placed",
           exchange: "orders-events", type: "order.placed.v2")

mq.consume("orders.new") do |message|
  message.payload          # => { "order_id" => "A-1" }
  message.envelope.attempt # => which delivery this is
  warehouse.reserve(message.payload) ? Ack.accept : Ack.retry("the warehouse said no")
end
```

[Getting started](getting-started.md) takes this apart line by line.

## What it does for you

**An envelope on every message.** Identity, type, version, correlation,
causation, attempt count, origin and the time it was first published — the same
fields Java, Go, .NET and Python write, so a message crossing between them keeps
its history. Application headers are kept apart from those, and a reserved name
in your own headers raises rather than being dropped. See
[the envelope](envelope.md).

**Retries that stop, and wait in the right place.** A handler returns
`Ack.retry`, and a policy decides whether there is another attempt and how long
to wait. A short wait happens in the consumer; a long one happens in the broker,
in a rung queue whose time-to-live is the delay — because a consumer that sleeps
through a five-minute backoff loses the whole wait when it restarts. See
[retries, dead letters and shutdown](reliability.md).

**Nothing to install to read a message.** The gem has no runtime dependencies.
`bunny` is required lazily, at the moment a connection is opened, and named in
the error if it is not there, so a process that only builds envelopes or checks
a retry schedule needs no broker client at all. See
[testing without a broker](testing.md).

**Security you have to opt out of.** An `amqps://` URL is encrypted *and
verified*, which is not what the underlying driver does on its own — see
[security](security.md), which explains the bunny behaviour this library exists
to correct. Credentials are a separate object so the password never goes in the
URL, and they render redacted through `inspect`, `to_s` and `%p` alike.

**A seam for the things no library can guess.** A tenant, a trace context, a log
scope, a size limit. [Interceptors](interceptors.md) wrap publishing and
handling without anybody editing the engine.

**Queues declared the way the other libraries declare them.** A durable, named
queue is a quorum queue, because `x-queue-type` is part of a queue's identity to
the broker and the second service to declare `orders` differently cannot consume
at all. See [queue types](topology.md#queue-types).

**Numbers and an honest readiness answer.** Metric names shared with the other
four libraries, an in-memory registry with a Prometheus renderer, and a health
report that calls a stopped consumer under a live connection *degraded* rather
than down. See [metrics and health](observability.md).

**The things everybody writes anyway, written once.** Idempotency, the outbox,
request and reply, replay, ordering, consumer groups, routing slips, pipelines,
schemas and streams. Required separately, because none of it is protocol. See
[patterns](patterns.md).

## What is identical, and what is not

**Identical**, because a message crosses languages: the reserved header names
and their types, the defaults applied when they are absent, the retry schedule
arithmetic, the `{queue}.dlq` / `{queue}.parked` / `{queue}.retry.{delay}`
naming, and the rules for giving up.

**Not identical**, deliberately: the API shape. Go gets `ctx`, .NET gets
`IAsyncEnumerable`, Python gets dataclasses, and Ruby gets keyword arguments,
frozen value objects, blocks and `?` predicates. Forcing a Java shape onto Ruby
produces a library nobody enjoys using. The contract is portable; the ergonomics
are native.

Concretely, that means: `Envelope` and `Credentials` are frozen after
construction and changed with `with`; a handler is a block that returns an
`Ack`; every optional argument is a keyword argument; and a pattern that wraps a
handler hands back a block you pass straight to `consume`.

## The layout

Everything lives under `AceMQ::AMQP`, in one gem, with the patterns behind a
second `require`:

| | |
|---|---|
| `acemq/amqp` | envelopes, headers, codecs, retry policy, topology, the connection and the transport |
| `acemq/amqp/patterns` | idempotency, outbox, request-reply, replay, ordering, consumer groups, routing slips, sagas, scheduling, pipelines, schemas, streams |

```ruby
require "acemq/amqp"
require "acemq/amqp/patterns"   # only if you use them
```

`include AceMQ::AMQP` at the top of a file is how the examples here are written,
because `Connection`, `Topology`, `Ack` and `RetryPolicy` read better than the
fully qualified names at every call site. Nothing depends on it — qualify them
if you would rather.

## Installing

```ruby
# Gemfile
gem "acemq-amqp"
gem "bunny", "~> 2.23"   # for the transport
```

Ruby 3.1 or newer. RabbitMQ for the broker.

The gem itself declares no runtime dependencies, and three of the [nine
codecs](serialization.md) are the only other things that ever ask for one. Each
requires its gem lazily and names it when it is missing:

```ruby
gem "rexml", "~> 3.3"             # XMLCodec. Ships with Ruby, but is a bundled
                                  # gem since 3.4, so Bundler needs it named.
gem "google-protobuf", "~> 4.29"  # ProtobufCodec
gem "avro", "~> 1.12"             # AvroCodec
```

Nothing is published to rubygems.org yet, so for now this is a git or path
source. The [releasing section of the
README](https://github.com/AceMQ-Company/acemq-ruby-amqp#releasing) says what
has to happen before it is.

## Status

Pre-1.0 and in development. The contract layer and the AMQP transport —
connect, publish, consume, retry, dead-letter — are implemented and tested,
against the shared fixtures and against a real broker, and so are the patterns
above them. TLS and credentials are in, including a private certificate
authority and mutual TLS. The API may change before 1.0.
